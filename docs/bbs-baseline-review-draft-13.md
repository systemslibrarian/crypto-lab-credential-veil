The review read the numbered draft's procedures and input domains against
`src/bbs/bbs.ts`, `generators.ts` and `ciphersuite.ts`. It also read the pinned
publisher fixture-population code. That tooling populates documents from
committed values; it does not generate the cryptographic vectors. No claim is
made to have regenerated the publisher's fixtures with their original engine.

All 30 fixture files match the selected upstream commit byte for byte. The
numbered draft includes the primary SHA-256 vectors and additional cases;
the publisher repository supplies the full local 10-signature/15-proof corpus.
Tests use publisher outputs, not outputs generated by this lab as expectations.

## Draft-12 to draft-13 comparison

Compared the two numbered IETF text publications (the previous draft-12 hash is
`9f2123df0f33ee8c5ffa75efb746f71e24eafd2e895ab8ba3245eaf6bc5be409`;
the active draft-13 hash is in the manifest). This comparison is against published
versions, not just the publisher's document-history summary.

- Sections 1 and 3.3.7 refine unlinkability and the issuer/verifier experiment;
  section 6.1 adds concrete-security assumptions; Appendix F maps the research
  paper to the procedures. These do not validate the custom age-proof extension.
- Sections 3.6–3.7 reorganize proof helper arguments into `ProofInitRes`, move
  randomness generation into initialization, and use a multi-exponentiation
  helper. The lab retains separately passed arguments and explicit point sums.
  Reviewed B, Abar, Bbar, D, T1, T2, response scalars and serialized challenge
  inputs: for the declared standard BBS interface these compute the same
  equations/transcript. This is not a claim that exported low-level helper
  signatures mirror the draft-13 object API. Existing stricter key/scalar/index
  checks remain; custom composition helpers are outside the standard interface.
- Section 4.2.3 now explicitly aborts for zero signed messages (`L == 0`). The
  shared domain helper now rejects this case, affecting signing, verification
  and proof operations. An empty message *value* and zero *disclosed* messages
  remain supported. The six-field credential demo is unchanged.
- Section 4.2.4 introduces multi-exponentiation; serialization moves to 4.2.5.
  The selected publisher commit includes the domain `L = length(generators)-1`
  and loop-end `length(scalars)-1` corrections present in published draft-13.
  We checked the numbered publication rather than assuming those edits were
  subsequent errata. Existing lab indexing already agrees.
- All 485 extracted hexadecimal byte strings/scalars in section 8 and Appendix D
  match between numbered drafts after removing page furniture and joining wrapped
  hex values. Draft-13 changes scalar notation from quoted `0x'…'` to `0x…`.
  All 30 publisher SHA-256 fixture files also match the previous snapshot and
  local bytes exactly. No publisher expected output was regenerated or changed.

The new regression case captures a zero-message signature and proof accepted by
lab commit `51e6c70` before the change, then requires the upgraded interface to
reject them. It is explicitly labeled local regression evidence, not a publisher
vector. Positive tests retain empty-valued messages and none/some/all disclosure.

For hash-to-scalar DST length, the implementation follows section 4.2.2's
explicit abort rule (>255 bytes). Its prose also says "less than 255"; this
minor wording inconsistency is not silently treated as a new protocol rule.
The implemented fixed domain tags are well below either boundary.

## Boundaries of this evidence

This establishes the declared SHA-256 BBS core baseline and its publisher-vector
compatibility. It is not a certification of every optional ciphersuite/interface,
constant-time behavior, browser entropy, production privacy or a complete wallet.
Typed low-level helpers assume the declared point/byte input types; they are not
general untrusted-object decoders. Generator/ciphersuite assumptions and published
security-model conditions remain necessary.

The integer-DOB mapping and the additional age-predicate challenge transcript
are custom teaching extensions. Their existing adversarial tests remain in the
suite, but the BBS draft vectors do not validate that composition. They remain
clearly disclosed in the demo, README and design note.

The original July source revision remains unknown. Current fixture bytes and
previous provenance are preserved in Git at `de715f85a46ceb98b7cbbf013c451e193da78e07`;
the new active baseline is not retroactively claimed to be that original source.
